> **版本**：v2.0
> **更新日期**：2026-08-07
> **说明**：本文档为两系统共同参考的“总控清单”，变更由人工同步到两侧仓库


## 一、项目背景与目标

两个系统（项目A · 主投研系统、项目B · 投前研究系统）已完成基础设施建设与跨系统联调，当前进入**应用层深化**阶段：

- **目标1**：策略规则定义 → 契约导出 → 策略级别回测 → 策略优化，形成闭环
- **目标2**：人机对比分析（项目B分析引擎已就绪，等待项目A数据积累）
- **目标3**：策略参数扫描标准化与因子有效性回溯


## 二、两系统共同约定（不可变更）

| ID | 内容 |
|---|---|
| M-001 | 策略链路分离：项目A负责策略规则定义与契约导出，项目B负责策略级别回测验证；模拟链路/实际链路独立存储，仅在 `human_machine_compare` 阶段对比 |
| M-002 | 应用层讨论时明确区分模拟链路（“策略本身行不行”）和实际链路（“我执行得怎么样”） |
| M-003 | 单向数据流：B → 共享目录 → A。B只写 `systemB_ref/`，A只读、只写 `systemA_feedback/` 消费回执；B严禁读取 `systemA_feedback/` |
| M-004 | A侧硬约束：①禁止策略名称路由；②买卖指令≥3条理由；③紧急停止按钮 |
| M-005 | `human_machine_compare` 基于模拟链路（自动建议）和实际链路（真实交易）做对比 |
| M-006 | 共享目录物理标准：`D:\FF Project\data\integration\systemB_ref/{YYYYMMDD}/` + `systemA_feedback/consumed_{YYYYMMDD}.json` |
| M-007 | `human_machine_compare` 真实月报触发条件：`human_override_log` ≥30条且覆盖≥3策略（当前4条/1策略） |
